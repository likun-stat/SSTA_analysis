# SSTA_analysis

Probabilistic forecasting of sea-surface temperature anomalies (SSTA), 6 months ahead, using three independent model families built on the same reduced-dimension (EOF) representation and the same train/valid/test split, for a fair comparison:

- **D-EESN** — Deep Ensemble Echo State Network (McDermott & Wikle, 2019)
- **FNO-DSTM** — Fourier Neural Operator, direct space-time mapping
- **DSNO** — Dual-Stream Neural Operator

(A fourth family, GRU-based models, exists in the original project this was drawn from but is **not included here**.)

This README is a straightforward, run-it-yourself tutorial. For the full methodology and results write-up, see `report.pdf` (generated by `generate_report.R`).

## 1. Data

| File | What it is |
|---|---|
| `sst.mnmean.nc` | Raw monthly mean SST, global grid, NOAA ERSSTv6 |
| `sst_anomalies_extracted.nc` | Anomalies relative to a 1981–2020 baseline, Jan 1970 – Apr 2026, ocean grid only |
| `eof_results.RData` | Precomputed spatial EOF basis (`Psi_K`, 27 retained modes, chosen by a permutation scree test — see `eof_analysis.R`) and the resulting PC time series `A_K` (676 months × 27 EOFs) |
| `eof_gru_data.RData` | Precomputed train/valid/test split (`n_train`, `n_valid`, `n_test`, `inner_train_frac`) shared by all three models. **Despite the filename, this contains no GRU model or GRU-specific content** — just split indices, kept from the original project's naming. |
| `perm_t2r.RData` | A grid-index permutation used only by FNO-DSTM's physical-space scoring step |

All three models work on the 27-dimensional EOF coefficient series `A_K`, not the raw spatial grid directly (except FNO-DSTM, which maps grid-to-grid but still uses the same train/valid/test month boundaries).

You do **not** need to regenerate `eof_results.RData` or `eof_gru_data.RData` to run the models below — they're already provided. `eof_analysis.R` is included for transparency/reproducibility (fixed seed, deterministic) if you ever want to rebuild the EOF basis from scratch.

## 2. Setup

Install R packages:

```r
install.packages(c("ncdf4", "fields", "Rcpp", "RcppArmadillo", "RcppEigen", "RcppTN", "inline"))
# torch (R interface to libtorch) -- see https://torch.mlverse.org/docs/articles/installation.html
install.packages("torch"); torch::install_torch()
```

D-EESN additionally needs the authors' own vendored code, included here under `BD-EESN/` (McDermott & Wikle's public implementation, `github.com/schafert/BD-EESN`). It compiles a small C++ file via Rcpp the first time it's sourced — no separate build step needed, just the packages above.

All scripts assume your working directory is this folder.

## 3. Running each model

Each model follows the same three-stage pattern: **tune** (grid search over architecture hyperparameters, scored by validation CRPS) → **fit** (train the winning config, evaluate on the held-out test set) → **predict** (train on *all* available months, forecast October 2026 — 6 months past the last observed month, April 2026).

### D-EESN

```r
source("deesn_tune_h6.R")        # ~10s.  Grid search over (numLayers, layerOneDimRed).
                                  # Saves deesn_tune_h6_results.rds.
source("deesn_fit_h6.R")         # ~1-3 min. E=500 reservoirs, test-set CRPS/coverage/extreme scores.
                                  # Saves deesn_h6_comparison.rds.
source("deesn_predict_oct2026.R") # ~2-3 min. Trains on all 676 months, forecasts Oct 2026.
                                  # Saves final_deesn_oct2026.rds and .pdf.
```

### DSNO (Dual-Stream Neural Operator)

```r
source("dsno_tune_h6.R")         # ~10-15 min. Grid search over (K, D), fixed W=36.
                                  # Saves dsno_tune_h6_results.rds.
source("dsno_fit_h6.R")          # ~10-20 min. E=500 networks, test-set scores.
                                  # Saves dsno_h6_comparison.rds.
source("final_predict_dsno.R")   # ~10-20 min. All 676 months, Oct 2026 forecast.
                                  # Saves final_dsno_oct2026.rds and .pdf.
```

A bonus, fully self-contained supplementary script, `chris_exact_replicate.R`, reruns DSNO with the hyperparameters from Wikle's own published example (`p=10, K=5, W=36, D=4`) instead of this study's tuned config, as a sanity check against the source implementation. Not required for the main pipeline.

### FNO-DSTM (Fourier Neural Operator, direct)

```r
source("fno_dstm2d_tune_h6.R")       # ~1-2 hr. Grid search over (width, modes_lon, modes_lat).
                                      # Saves fno_dstm2d_tune_h6_results.rds.
source("fno_dstm2d_fit_h6_tuned.R")  # ~10-15 min. Tuned config, test-set scores (EOF + physical-grid space).
                                      # Saves fno_dstm2d_h6_tuned_comparison.rds and fno_dstm2d_h6_tuned_raw.rds.
source("final_predict_fno_dst.R")    # ~75-90 min. 10 seeds x 1000-member ensemble, all 676 months, Oct 2026.
                                      # Saves final_fno_dst_oct2026.rds and .pdf.
```

FNO-DSTM is by far the most expensive of the three (tuning alone dominates; the final forecast re-fits 10 independent seeds). Everything runs on CPU — no GPU is required or used.

There is also an *untuned* baseline fit, `fno_dstm2d_fit_h6.R`, kept for reference in the original project; it is **not** part of the best-settings pipeline above and depends on a GRU-derived comparison file not included here, so don't run it as-is.

## 4. What you get

Each `final_<model>_oct2026.rds` contains the October 2026 forecast as an ensemble of draws in EOF-coefficient space (`draws_pc`), reconstructed to the physical grid, plus summary stats (median, mean, 90% interval). Each `final_<model>_oct2026.pdf` plots the forecast field with uncertainty bands. The `<model>_h6_comparison.rds` / `<model>_tuned_comparison.rds` files hold test-set scores: MSE, CRPS, threshold-weighted CRPS at the 90th/95th percentile (extreme-event skill), and empirical coverage at the 50/80/90/95% levels.

To reproduce the comparison report included in this directory (`report.pdf`), run `generate_report.R` after all three pipelines above have completed.
